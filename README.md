# 日签云端推送系统

**电脑关机也能收到**：GitHub Actions 每天北京时间 07:25 自动触发，把当天封面图和提醒文字推到手机。

- **主通道（A）**：企业微信群机器人 → 原生图片消息，手机长按直接存相册 + 文字提醒
- **兜底通道（C）**：Server酱 → 微信服务号文字提醒，随时可复制文案
- 两条通道互相独立，一条挂了另一条照送

---

## 一次性配置（约 5 分钟）

### 第 1 步 · 企业微信群机器人（主通道）

1. 装企业微信，建一个**只有自己**的群（群名随意，如「日签提醒」）
2. 群右上角「…」→「群机器人」→「添加机器人」→ 命名「日签推送」
3. 复制 Webhook 地址，形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx`
4. 收好，第 3 步要用

### 第 2 步 · Server酱（兜底通道）

1. 打开 `https://sct.ftqq.com`，微信扫码登录（免实名）
2. 复制 SendKey（`SCT` 开头的一串）
3. **微信里关注它的服务号并绑定**，否则收不到消息
4. 免费版每天 5 条，日签每天 1 条，够用

### 第 3 步 · 填 GitHub Secrets

仓库 → `Settings` → `Secrets and variables` → `Actions` → `New repository secret`，逐条添加：

| Secret 名称 | 填什么 | 必填 |
|---|---|---|
| `WECOM_WEBHOOK` | 第 1 步的企业微信 Webhook 完整地址 | 是（主通道） |
| `SERVERCHAN_KEY` | 第 2 步的 SendKey | 是（兜底） |
| `IMAGE_URL_BASE` | 图床地址前缀，如 `https://cdn.xxx.com/daily` | 否，留空则 Server酱 只推文字 |

> 密钥只存在 Secrets 里，不进代码、不进日志。

### 第 4 步 · 手动测试

`Actions` 标签 → 左侧选「日签推送 · 企业微信主 + Server酱兜底」→ `Run workflow` → 日期框填 `11-24` → 运行。

验收标准：日志出现「推送完成，成功通道数: 2」，且企业微信收到图片 + 文字、微信服务号收到文字。

## 日常使用

全自动，无需电脑。手机收到推送后按消息里的 6 步操作即可：

1. 订阅号助手 → 底部「贴图」
2. 从相册选今天的封面图（长按推送里的图片保存）
3. 粘贴标题 + 描述，末尾带话题
4. 打开「允许平台推荐」← 最关键
5. 点「发表」
6. 右上「…」→「分享到朋友圈」→ 粘贴配文 → 发表

> 贴图不能存草稿、不从草稿箱发，每天必须从贴图入口新建。

电脑开着时，现有的本地 07:25 提醒保留作第三重保险，不冲突。

## 内容更新（12-05 之后）

当前内容包覆盖 **11-24 ~ 12-05**。要延长排期：

1. 编辑 `data/daily_content.json`，在 `days` 数组里照现有格式加新条目
2. 新封面图转 base64 存进 `assets/`（文件名与 JSON 的 `asset` 字段一致）：

```bash
base64 -w0 "日签封面_13_12-06.png" > assets/day13.b64
```

3. `git commit` 并 push，次日 07:25 自动生效

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| Actions 红色失败，日志「未配置密钥」 | Secrets 没填或名字拼错 | 核对 3 个 Secret 名称 |
| 企业微信没收到 | Webhook 过期 / 机器人被删 | 重建机器人，换新 Webhook |
| 微信服务号没收到 | 没关注或没绑定 Server酱服务号 | 微信里关注并绑定 |
| 图片不显示 | `.b64` 文件内容损坏 | 重新用 `base64 -w0` 生成 |
| 某天完全没推送 | 日期不在 JSON 排期内 | 更新 `daily_content.json` |
| 推送延迟几分钟 | GitHub Actions 高峰排队 | 正常现象，07:25 通常准点 |

## 合规与安全

- 密钥只存 GitHub Secrets，不进代码、不进日志
- 推送目标只有账号本人，不对外群发，不调用公众号发布接口
- 文案与封面均为已对外公开的日签内容，无敏感信息
- 最后一步「发表」始终由本人人工点击，系统不代发

## 技术说明

- 定时规则：`cron: '25 23 * * *'`（UTC 23:25 = 北京 07:25）
- GitHub Actions 在整点/高峰可能排队延迟数分钟，属正常现象
- 仓库建议保持**私有**：公开仓库 60 天无提交活动会被 GitHub 暂停定时任务
- 企业微信图片用原生 `image` 消息（base64 + md5），不依赖公网图床
- Server酱图片可选，需自配图床；不配则只推文字，图片以企业微信为准
